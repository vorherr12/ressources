Modèles réseau & Couche physique

Le Modèle OSI (Open Systems Interconnection)

Créé par l'ISO (International Standards Organisation) en 1978 et révisé en 1984, le modèle OSI est un modèle de référence théorique. Son but principal était de mettre fin à la guerre des architectures propriétaires (comme SNA d'IBM, DECnet de Digital Equipment ou AppleTalk d'Apple) en fournissant un standard universel d'interopérabilité.

Avant l'OSI, chaque constructeur disposait de son propre protocole. Un ordinateur IBM ne pouvait pas dialoguer avec un ordinateur DEC. Ce cloisonnement, coûteux et inefficace, a motivé la création d'un cadre commun que tous pourraient respecter. Bien que le modèle OSI n'ait jamais été implémenté tel quel en production (le modèle TCP/IP a gagné la bataille), il reste la référence universelle pour comprendre et enseigner les réseaux.

Le modèle OSI découpe la communication en 7 couches, obéissant à des règles strictes :

  • Indépendance des couches : Chaque couche a un rôle hyper-spécialisé. Modifier la technologie d'une couche (ex: passer du cuivre au WiFi en couche 1) n'impacte pas les autres couches. C'est le principe de l'abstraction : la couche 4 (TCP) n'a pas besoin de savoir si les données voyagent sur du cuivre, de la fibre ou du WiFi.
  • Communication adjacente : La couche N ne peut dialoguer qu'avec la couche N-1 (pour confier des données) et la couche N+1 (pour en recevoir). Les communications entre les couches doivent être réduites au maximum pour maintenir la modularité.
  • Communication virtuelle (Peer-to-Peer) : Logiquement, la couche 4 de l'émetteur "parle" à la couche 4 du récepteur, en utilisant le même protocole. Physiquement, les données descendent toutes les couches de l'émetteur, traversent le médium physique, puis remontent toutes les couches du récepteur.
  • Pas de doublons fonctionnels : Si la couche 4 gère la fiabilité (retransmission), aucune autre couche ne doit refaire ce travail. Chaque fonction n'est implémentée qu'à un seul endroit.

Les sous-couches de la Couche 2 en détail

La couche 2 est unique dans le modèle OSI car elle est divisée en deux sous-couches distinctes, chacune ayant un rôle critique :

  • LLC (Logical Link Control — IEEE 802.2) : Située au-dessus de MAC, elle sert d'interface avec la couche 3 (Réseau). Elle identifie quel protocole de couche 3 doit recevoir les données (IPv4, IPv6, ARP). Dans les trames Ethernet II modernes, cette fonction est assurée par le champ EtherType. Le LLC est davantage utilisé dans les trames de contrôle (ex: les BPDU du Spanning Tree Protocol).
  • MAC (Media Access Control — IEEE 802.3) : C'est la sous-couche qui gère l'accès au médium physique et l'adressage matériel. Elle décide quand une station a le droit d'émettre sur le câble (CSMA/CD) et à qui la trame est destinée (adresse MAC).

Le Modèle TCP/IP (Modèle Internet)

Contrairement à l'OSI qui est théorique, le modèle TCP/IP (issu du projet ARPANET du DoD américain, adopté en 1983) est le modèle pratique qui fait fonctionner Internet. Il est plus pragmatique et regroupe les fonctions en 4 niveaux seulement.

Le nom "TCP/IP" désigne en réalité une suite (stack) de protocoles dont les deux principaux sont TCP (Transport) et IP (Réseau). L'avantage de cette simplification est que le modèle est directement implémentable en code dans les systèmes d'exploitation (pile TCP/IP du noyau Linux, de Windows...).

C'est cette souplesse qui a permis à Internet de survivre à toutes les évolutions technologiques depuis 40 ans.

En examen ou en entretien, maîtriser les deux est indispensable. En pratique sur le terrain, on raisonne presque toujours avec les couches de TCP/IP.

L'encapsulation : Le voyage de la donnée

L'encapsulation est le processus par lequel les données se voient ajouter des informations de contrôle (en-têtes et parfois des suffixes) au fur et à mesure qu'elles descendent les couches du modèle OSI vers le support physique. C'est le principe des poupées russes (matriochkas) : chaque couche "emballe" les données dans une nouvelle enveloppe.

Processus détaillé

  • Émission (Encapsulation — de haut en bas) : La donnée brute de l'application (ex: une page HTML) reçoit un en-tête de Transport (Port Source/Dest) devenant un Segment (TCP) ou un Datagramme (UDP). Puis un en-tête Réseau (IP Source/Dest, TTL, Protocole) devenant un Paquet. Puis un en-tête Liaison (MAC Source/Dest) et un suffixe de vérification (FCS) devenant une Trame. Enfin, la trame est convertie en Bits (signaux électriques/optiques/radio) par la couche Physique.
  • Réception (Décapsulation — de bas en haut) : La carte réseau lit la Trame, vérifie si l'adresse MAC de destination lui correspond ou s'il s'agit d'un broadcast. Si oui, elle vérifie l'intégrité (FCS), retire l'en-tête MAC et transmet le Paquet à la couche IP. L'IP vérifie l'adresse de destination, lit le champ "Protocole" pour savoir à qui transmettre (TCP=6, UDP=17, ICMP=1), retire l'en-tête IP, et ainsi de suite jusqu'à l'application.

Exemple concret pas à pas

Un agent DGFiP tape http://si.intranet.dgfip dans Firefox. Voici ce qui se passe dans l'ordre :

  1. Couche 7 (Application) : Firefox construit une requête HTTP : GET / HTTP/1.1\r\nHost: si.intranet.dgfip\r\n...
  2. Couche 4 (Transport) : La pile TCP ajoute un en-tête avec Port Source: 52341 (aléatoire) et Port Dest: 80 (HTTP).
  3. Couche 3 (Réseau) : La pile IP ajoute IP Source: 10.31.78.102 et IP Dest: 10.154.96.38 (résolu par DNS), TTL: 128.
  4. Couche 2 (Liaison) : La carte réseau consulte le cache ARP. L'IP de destination étant sur un autre réseau (/22), elle cherche la MAC de la passerelle (10.31.76.1). Elle emballe le tout avec MAC Source: carte de l'agent et MAC Dest: MAC du routeur, plus un FCS.
  5. Couche 1 (Physique) : Les bits sont convertis en impulsions électriques sur le câble RJ45.
⚠️

Point essentiel : L'encapsulation crée un overhead (surcharge). Sur une trame Ethernet de 1518 octets max, 18 octets sont consommés par l'en-tête Ethernet (14) + FCS (4), 20 par l'IP, 20 par TCP. Il ne reste donc que 1460 octets de données utiles (payload) sur les 1518 — c'est le MSS (Maximum Segment Size) standard. Cette valeur est négociée lors du 3-way handshake TCP.

Couche 1 — Infrastructure et Liaison physique

La couche 1 ne comprend pas la notion de données. Elle ne voit que des signaux (impulsions électriques, flashs lumineux, ou ondes radio) représentant des 0 et des 1. Elle définit les spécifications des supports de transmission et des connecteurs : cuivre, fibre optique, et air (WiFi, Bluetooth). Son déploiement est encadré à la DGFiP par la Charte LAN.

Topologie du VDI (Voix, Données, Images) dans un bâtiment

Le câblage d'un bâtiment professionnel suit une architecture hiérarchique normalisée. C'est le VDI : un câblage unique conçu pour transporter indifféremment la voix (téléphone IP), les données (réseau informatique) et les images (vidéosurveillance, IPTV).

  • Câblage vertical (Rocades ou Backbone) : Ce sont les artères principales du bâtiment. Elles relient les différents étages (LTE) au cœur de réseau (LTI). Elles exigent une très haute bande passante et sont quasi-exclusivement réalisées en fibre optique. La redondance est systématique : deux chemins physiques distincts (idéalement empruntant des colonnes différentes) relient chaque LTE au LTI.
  • Câblage horizontal (Capillaire) : Ce sont les veines qui irriguent les bureaux. Elles relient le switch de l'étage (dans le LTE) aux prises murales RJ45 des utilisateurs. La norme impose que le lien permanent (du bandeau de brassage à la prise murale, sans les cordons) ne dépasse pas 90 mètres. En ajoutant les cordons de brassage (max 5 m côté LTE) et le cordon utilisateur (max 5 m côté prise murale), la distance totale ne dépasse pas 100 mètres.

Locaux techniques et Environnement

Les équipements réseau génèrent de la chaleur et sont critiques pour le fonctionnement de l'administration. Les locaux (LTI/LTE) doivent répondre à des normes strictes :

  • LTI (Local Technique d'Immeuble) : Point de démarcation avec les opérateurs (Arrivée WAN/RIE). Il héberge les routeurs, les cœurs de réseau (switches L3) et éventuellement les serveurs locaux. Il nécessite une climatisation redondée (deux climatiseurs, un actif et un en secours), un accès sécurisé (badge, journal d'accès), et une alimentation secourue par onduleurs (UPS) de forte capacité capables de tenir pendant au moins 15 à 30 minutes en cas de coupure électrique, le temps que le groupe électrogène prenne le relais. Le LTI regroupe également les départs des rocades fibre vers chaque LTE et les liaisons vers les serveurs.
  • LTE (Local Technique d'Étage) : Souvent un simple placard technique ventilé (ventilation forcée ou passive). Il regroupe les switches d'accès (L2) qui distribuent le réseau aux PC de l'étage via les câbles horizontaux. Il doit être fermé à clé pour empêcher les manipulations non autorisées et contenir au minimum une armoire de brassage normalisée (format 19 pouces).

L'art du Brassage et la Recette

Dans une baie de brassage (armoire standardisée de 19 pouces de large), les câbles venant des murs ne sont jamais branchés directement sur les switches. Ils sont terminés (sertis) à l'arrière d'un bandeau de brassage (panneau passif constitué d'une rangée de prises RJ45 numérotées). On utilise ensuite des cordons de brassage souples pour relier l'avant du bandeau au port correspondant du switch.

Pourquoi cette architecture indirecte ? Pour protéger le câblage horizontal (rigide, installé dans les faux-plafonds et les gaines, impossible à remplacer facilement). Le brassage permet de changer l'affectation d'une prise (téléphone, réseau, imprimante, ou même la désactiver) en déplaçant simplement un petit cordon souple de quelques centimètres. Il est normalement interdit de débrancher ou brancher un câble à l'arrière du bandeau de brassage, car cela risque d'endommager le lien permanent.

Recette de câblage : Opération obligatoire en fin de chantier, réalisée par le SIL (Service Informatique Local) avec un certificateur FLUKE 1800 (ou équivalent). L'appareil injecte des fréquences dans chaque câble pour mesurer :

  • L'atténuation (Insertion Loss) : Perte de signal entre l'émission et la réception. Si trop élevée, le câble est trop long ou endommagé.
  • La diaphonie (Crosstalk — NEXT/FEXT) : Interférence entre les paires internes du câble. Un excès de diaphonie provoque des erreurs CRC.
  • La longueur : Mesurée par réflectométrie (TDR). Si elle dépasse 90 m, le câble est hors norme.
  • Le schéma de câblage (Wire Map) : Vérifie que les 8 fils sont connectés dans le bon ordre (T568A ou T568B) et qu'il n'y a pas de fils croisés, inversés, ou de court-circuits.

Si le câble réussit tous les tests, il est "certifié" pour un débit donné (ex: Cat 6a = 10 Gbps). Un rapport de certification est généré et archivé pour chaque lien. Ce document est exigé par la Charte LAN DGFiP et peut être réclamé lors d'audits.

Câblage cuivre (Paires Torsadées)

Pourquoi torsader les fils ? (La Diaphonie)

Un câble réseau cuivre (Twisted Pair) contient 8 fils organisés en 4 paires. Chaque paire transporte un signal différentiel (le signal utile est la différence de tension entre les deux fils de la même paire). Lorsqu'un courant traverse un fil, il génère un champ électromagnétique qui perturbe les fils voisins : c'est la diaphonie (Crosstalk).

En torsadant les fils d'une même paire ensemble, les champs magnétiques parasites s'annulent mutuellement (principe de la paire différentielle). Plus il y a de torsades par mètre, plus le câble supporte de hautes fréquences. C'est pourquoi un câble Cat 6a (500 MHz) a des paires plus serrément torsadées qu'un Cat 5e (100 MHz).

Types de diaphonie mesurés

  • NEXT (Near-End Crosstalk) : Diaphonie mesurée à l'extrémité émettrice. C'est la plus critique car le signal parasite est au plus fort à ce point.
  • FEXT (Far-End Crosstalk) : Diaphonie mesurée à l'extrémité réceptrice. Moins critique car le signal parasite est aussi atténué par la distance.
  • Alien Crosstalk (AXT) : Diaphonie entre deux câbles différents placés côte à côte dans la même gaine. C'est le facteur limitant principal en Cat 6a. C'est pourquoi les câbles Cat 6a sont plus épais (blindage individuel des paires).

Altérations du signal cuivre

En plus de la diaphonie, le signal cuivre souffre d'autres dégradations qu'il est essentiel de comprendre pour diagnostiquer les problèmes terrain :

  • Atténuation : Perte progressive de la puissance du signal avec la distance. Plus la fréquence est élevée, plus l'atténuation est forte — c'est pourquoi la limite de 90 m est absolue et non négociable.
  • Réflexion (Return Loss) : Lorsque le signal rencontre un changement d'impédance (mauvais sertissage, connecteur de mauvaise qualité, coude trop serré), une partie de l'énergie est renvoyée vers l'émetteur, créant des échos.
  • Latence de propagation : Temps que met le signal pour parcourir le câble. Si les 4 paires n'ont pas exactement la même longueur (à cause des torsades différentes), les signaux arrivent avec un décalage (Delay Skew), ce qui peut provoquer des erreurs en Gigabit Ethernet.

Nomenclature des blindages (Norme ISO 11801)

Le blindage protège le câble des parasites extérieurs (moteurs, tubes fluorescents, câbles électriques). La nomenclature est BlindageGlobal / BlindagePaire TP.

  • U (Unshielded) : Aucun blindage.
  • F (Foil) : Blindage par feuillard (une feuille d'aluminium fin). Protège efficacement contre les hautes fréquences mais offre peu de résistance mécanique.
  • S (Shielded) : Blindage par tresse de cuivre. Protège contre les basses fréquences et offre une meilleure résistance mécanique et une meilleure mise à la terre.

Connecteurs RJ45

Le connecteur RJ45 (Registered Jack 45) est un connecteur 8P8C (8 positions, 8 contacts). Il existe deux normes de câblage des fils à l'intérieur du connecteur :

  • T568A : Standard recommandé (couleurs : blanc-vert, vert, blanc-orange, bleu, blanc-bleu, orange, blanc-marron, marron).
  • T568B : Le plus utilisé aux États-Unis et dans beaucoup d'installations existantes. Les paires 2 et 3 sont inversées par rapport au T568A.

Câble droit vs croisé : Un câble droit (même norme aux deux bouts : A-A ou B-B) relie un PC à un switch. Un câble croisé (normes différentes aux deux bouts : A-B) reliait historiquement deux PC directement ou deux switches entre eux. Aujourd'hui, la fonction Auto-MDI/MDIX des cartes réseau et switches modernes détecte automatiquement le type de câble, rendant les câbles croisés obsolètes.

Le PoE (Power over Ethernet)

Les câbles cuivre modernes ne transportent plus seulement de la data. Avec la norme PoE (802.3af/at/bt), le switch injecte du courant électrique dans le câble RJ45 pour alimenter directement les équipements terminaux, supprimant le besoin de prises électriques dédiées.

Fibre optique

La fibre optique transmet l'information sous forme d'impulsions lumineuses à travers un fil de verre ou de plastique ultra-pur (silice). Elle est insensible aux interférences électromagnétiques (EMI) et ne génère aucune étincelle (idéal en milieu industriel, hospitalier ou extérieur). De plus, elle offre un niveau très fort de résistance au piratage physique : écouter une fibre optique est extrêmement difficile (contrairement au cuivre où il suffit d'un inductif).

Structure d'une fibre optique

Une fibre optique est composée de trois éléments concentriques :

  • Le cœur (Core) : Cylindre central en verre ultra-pur dans lequel la lumière se propage. Son diamètre varie de 9 µm (monomode) à 50 ou 62,5 µm (multimode).
  • La gaine optique (Cladding) : Enveloppe de verre de 125 µm de diamètre, avec un indice de réfraction inférieur au cœur. C'est cette différence d'indice qui confine la lumière dans le cœur par réflexion totale interne.
  • Le revêtement protecteur (Coating / Buffer) : Enveloppe plastique de protection mécanique. Elle peut être "serrée" (tight buffer, utilisée dans les jarretières internes) ou "lâche" (loose tube, utilisée dans les câbles extérieurs avec un gel protecteur).

Règles de déploiement

La fibre est techniquement obligatoire dans deux cas :

  1. La distance dépasse 90 mètres (limite physique de l'Ethernet sur cuivre pour le lien permanent).
  2. Liaison entre deux bâtiments distincts. Raison : Deux bâtiments ont des "terres" électriques différentes. Relier deux bâtiments par du cuivre crée une différence de potentiel qui peut foudroyer les équipements réseau (boucle de terre). La fibre, étant en verre, assure une isolation galvanique totale — aucun courant électrique ne peut la traverser.

Par rapport au cuivre, la fibre apporte plus d'évolutivité (on peut augmenter le débit en changeant simplement les transceivers sans retirer le câble) et de sécurité.

Jarretières optiques

Une jarretière optique est l'équivalent fibre d'un cordon de brassage cuivre. C'est un câble souple, court (1 à 5 mètres typiquement), terminé par des connecteurs aux deux extrémités. Elle relie le tiroir fibre (panneau de brassage optique) au transceiver SFP du switch.

Attention à la manipulation : La fibre a un rayon de courbure minimum (généralement 30 mm). Si vous pliez une jarretière plus que ce rayon, la lumière "s'échappe" du cœur par réfraction, provoquant une atténuation excessive voire la rupture de la fibre. Les guides de câbles dans les armoires doivent toujours respecter ce rayon.

Transceivers (SFP / SFP+) et Convertisseurs

Les switches modernes n'ont pas de ports fibre soudés. Ils possèdent des cages vides dans lesquelles on insère des modules enfichables :

  • SFP (Small Form-factor Pluggable) : Module 1 Gbps. Convertit le signal électrique du switch en signal optique. Disponible en version monomode (portée longue) ou multimode (portée courte).
  • SFP+ : Module 10 Gbps, même format physique que le SFP.
  • QSFP+ / QSFP28 : Modules 40 Gbps / 100 Gbps pour les liens inter-switches et Datacenter.
  • SFP cuivre (RJ45) : Un SFP qui au lieu d'un port optique propose un port RJ45. Pratique pour connecter un serveur proche sur un port SFP sans utiliser de fibre.

Cela permet d'adapter le switch à n'importe quel type de fibre simplement en changeant le module SFP. Il existe également des convertisseurs fibre/cuivre autonomes (media converters) utilisés quand le switch ne dispose pas de cage SFP — on les branche entre la fibre et le port RJ45 du switch.

Le WiFi (Wireless Fidelity) est une technologie de réseau local sans fil basée sur la famille de normes IEEE 802.11. Le signal radio est émis et reçu par des bornes d'accès (Access Points — AP) qui font le pont entre le monde sans fil et le réseau Ethernet filaire.

  • Si un employé part ou si la clé fuite, il faut changer le mot de passe sur tous les appareils.
  • Tous les utilisateurs partagent la même clé, il est impossible de savoir qui fait quoi (pas de traçabilité individuelle).
  • La clé PSK peut être capturée et crackée par attaque de force brute sur le 4-way handshake WPA2.

L'architecture 802.1X / EAP-TLS

Le réseau DGFiP utilise le standard 802.1X, qui s'appuie sur des certificats numériques (méthode EAP-TLS) pour une sécurité maximale. Chaque appareil possède son propre certificat : si un PC est volé, on révoque simplement son certificat sans impacter les autres. L'architecture fait intervenir 3 acteurs :

  1. Le Suppliant (Le PC portable) : L'appareil qui demande l'accès au réseau. Il possède un certificat numérique unique installé par la DSI lors du déploiement de la machine. Ce certificat contient la clé publique du PC et est signé par l'Autorité de Certification interne DGFiP.
  2. L'Authentificateur (La Borne WiFi / Contrôleur) : La borne diffuse le SSID (nom du réseau sans fil). Quand le PC s'y connecte, la borne bloque tout trafic data. Elle joue le rôle de vigile : elle demande l'identité du PC et transmet cette information au serveur de sécurité via le protocole RADIUS. La borne elle-même ne prend aucune décision d'authentification.
  3. Le Serveur d'Authentification (Serveur RADIUS) : C'est le cerveau de la sécurité. Il reçoit le certificat du PC via la borne. Il vérifie sa signature cryptographique (est-il bien signé par notre CA ?), sa date de validité (n'a-t-il pas expiré ?), et interroge la CRL (Certificate Revocation List) ou le protocole OCSP pour s'assurer que le PC n'a pas été déclaré volé, perdu ou compromis.

Déroulement d'une connexion réussie

Si le serveur RADIUS valide le certificat, il envoie un message "Access-Accept" à la borne WiFi. Ce message contient également des attributs RADIUS qui indiquent à la borne dans quel VLAN placer le PC (ex: VLAN 10 pour les agents, VLAN 20 pour les imprimantes). La borne déverrouille alors le port virtuel du PC, le place dans le bon VLAN (Réseau virtuel), et autorise le trafic IP. Le PC envoie alors une requête DHCP pour obtenir une adresse IP dans le bon sous-réseau. C'est seulement à ce moment-là que le PC est réellement "sur le réseau".

Si le certificat est invalide, expiré ou révoqué, le serveur RADIUS envoie un "Access-Reject". La borne refuse la connexion et le PC ne peut pas accéder au réseau. Un log est généré pour traçabilité.

💡

802.1X n'est pas réservé au WiFi ! Le même mécanisme peut être utilisé sur les ports filaires Ethernet. On parle alors de NAC (Network Access Control). Un PC non autorisé branché sur une prise murale sera bloqué par le switch tant qu'il n'a pas été authentifié par le serveur RADIUS. C'est une pratique de sécurité de plus en plus déployée dans les administrations.

Ethernet & Adresses MAC

L'adresse MAC (Media Access Control) est l'identité physique d'une carte réseau, gravée en usine par le constructeur. Contrairement à l'adresse IP qui est logique et routable à travers Internet, l'adresse MAC ne sert qu'à communiquer sur le réseau local (LAN). Elle est aussi appelée adresse physique, adresse Ethernet ou adresse matérielle.

Elle a été prévue pour être unique mondialement. Avec 48 bits (6 octets), on dispose de 2⁴⁸ = 281 474 976 710 656 adresses possibles, soit environ 281 000 milliards — largement suffisant pour identifier chaque carte réseau produite dans le monde.

Structure (48 bits / 6 octets)

L'adresse MAC est composée de 6 octets affichés en paires de chiffres hexadécimaux séparés par des deux-points (:) ou des tirets (-).

  • OUI (Organizationally Unique Identifier) : Les 3 premiers octets identifient le constructeur. Ce préfixe est attribué par l'IEEE. Exemples :
    • 00:1A:A0 → Dell Inc.
    • 00:50:56 → VMware (machines virtuelles)
    • d0:27:88 → Freebox SAS
    • 08:00:27 → Oracle Corporation (VirtualBox)
    Astuce Wireshark : Wireshark décode automatiquement l'OUI et affiche le nom du constructeur à côté de l'adresse MAC. Cela permet d'identifier rapidement le type d'équipement dans une capture.
  • NIC (Network Interface Controller) : Les 3 derniers octets forment un numéro de série unique attribué par le constructeur en usine. C'est ce qui différencie deux cartes réseau du même fabricant.
Adresse MAC : d0:27:88:7c:12:94 ├──────┤├──────┤ OUI NIC (Freebox) (Numéro de série) En binaire : 1101000 : 00100111 : 10001000 : 01111100 : 00010010 : 10010100 (48 bits au total)

Bits spéciaux dans l'OUI

Le premier octet de l'adresse MAC contient deux bits importants :

  • Bit 0 (I/G — Individual/Group) : Si ce bit vaut 0, l'adresse est unicast (destinée à une seule carte). S'il vaut 1, c'est une adresse multicast (destinée à un groupe). Exemple : 01:00:5e:xx:xx:xx — le premier octet 01 en binaire est 00000001, le bit 0 vaut 1 → multicast.
  • Bit 1 (U/L — Universal/Local) : Si ce bit vaut 0, l'adresse a été attribuée par l'IEEE (universelle). S'il vaut 1, elle a été modifiée localement (administration locale). Utile pour détecter les machines virtuelles ou le MAC spoofing.

En pratique sur le terrain

  • Trouver sa MAC :
    • Windows : ipconfig /all (champ "Adresse physique")
    • Linux : ip a ou ip link (champ "link/ether")
    • macOS : ifconfig en0 (champ "ether")
  • MAC Spoofing : Bien qu'inscrite "en dur" dans la puce, l'OS permet de la modifier logiciellement via le pilote réseau. C'est souvent utilisé pour :
    • Contourner un portail captif (ex: WiFi d'hôtel limité à 1h — on change sa MAC et on obtient une nouvelle session)
    • Usurper l'identité d'un équipement autorisé (contournement de filtrage MAC)
    • Préserver sa vie privée sur les réseaux publics (la MAC Address Randomization est activée par défaut sur iOS et Android modernes)

Le format le plus utilisé est Ethernet II (aussi appelé Ethernet v2 ou DIX), qui est celui que vous observerez dans 99% des captures Wireshark. Il existe aussi un format IEEE 802.3 (avec LLC/SNAP) utilisé par certains protocoles de contrôle (comme STP), mais il est plus rare dans le trafic applicatif normal.

D'où le padding si le payload fait moins de 46 octets.

Les trames BPDU du Spanning Tree Protocol n'utilisent pas le format Ethernet II mais le format IEEE 802.3 avec en-tête LLC. Le champ EtherType est remplacé par un champ "Length" (longueur du payload), suivi d'un en-tête LLC de 3 octets (DSAP=0x42, SSAP=0x42, Control=0x03) qui identifie le protocole STP. Cette distinction est visible dans Wireshark lors de l'analyse des BPDU.

Commutateurs (Switches) & Table MAC

Contrairement à un vieux Hub (concentrateur) qui répétait bêtement le signal électrique sur tous les ports (couche 1 uniquement), un Switch (commutateur) est intelligent. Il opère à la couche 2 et maintient une Table MAC (ou Table CAM — Content Addressable Memory) en RAM ultra-rapide.

Le Hub crée un unique domaine de collision : si deux machines émettent en même temps, il y a collision et les deux doivent réémettre. Le Switch crée un domaine de collision par port : chaque port est un segment isolé, les collisions deviennent quasi-impossibles en full-duplex. C'est la raison pour laquelle les Hubs ont totalement disparu des réseaux modernes.

Mécanismes de fonctionnement

L'apprentissage (Learning)
Quand une trame entre sur le port 1, le switch lit la MAC Source et note dans sa table : "La machine AA:AA:AA:AA:AA:AA est sur le port 1". Cette entrée expire généralement après 300 secondes (5 minutes) d'inactivité. C'est le aging time, configurable par l'administrateur.
Le transfert (Forwarding) vs L'inondation (Flooding)
Le switch lit la MAC Destination. S'il la trouve dans sa table (l'adresse est dite "connue"), il envoie la trame uniquement sur le bon port — c'est le forwarding. S'il ne la connaît pas (elle n'est pas dans la table, ou c'est un Broadcast ff:ff...), il fait du Flooding : il envoie une copie de la trame sur tous les ports du même VLAN sauf celui d'origine.
Le filtrage (Filtering)
Si la MAC de destination est sur le même port que la MAC source (les deux machines sont derrière le même hub ou sur le même segment), le switch ne retransmet pas la trame — il la filtre. Cela évite de polluer les autres ports inutilement.

Le Cut-Through est utilisé dans les switches haute performance de Datacenter (Arista, Cisco Nexus) où chaque microseconde compte.

Exemple de fonctionnement détaillé (Issu du cours DGFiP)

Considérons deux switches Sw1 et Sw2 reliés entre eux :

PC1 (AA:AA) ──[E1]── Sw1 ──[E0]──────[E5]── Sw2 ──[E3]── PC3 (CC:CC) PC2 (BB:BB) ──[E2]── │ │ ──[E4]── PC4 (DD:DD)

PC1 envoie une trame à PC4 (DD:DD:DD:DD:DD:DD) :

  1. Sw1 reçoit la trame sur E1. Il note : AA:AA → port E1.
  2. Sw1 lit la MAC destination DD:DD. Il ne la connaît pas dans sa table.
  3. Sw1 fait du Flooding : il envoie la trame sur E2 et E0 (tous les ports sauf E1).
  4. Sw2 reçoit la trame sur E5. Il note : AA:AA → port E5.
  5. Sw2 connaît DD:DD sur E4 (appris précédemment). Il envoie la trame uniquement sur E4.
  6. PC4 reçoit la trame. Communication réussie !
🛡️

Cybersécurité : L'attaque MAC Flooding
La table MAC a une taille limitée (ex: 8000 adresses sur un switch Cisco 2960). Un attaquant peut générer des milliers de fausses adresses MAC par seconde (outil macof de la suite dsniff). Une fois la table saturée, le switch ne peut plus rien apprendre et se met à "flooder" tout le trafic sur tous les ports, transformant le switch en hub. L'attaquant peut alors sniffer les conversations des autres avec Wireshark.

Parades :
① Port Security : Limiter le nombre de MAC autorisées par port (ex: 1 seule MAC sur un port PC).
② 802.1X : Authentifier chaque appareil avant de lui donner accès au réseau.
③ DHCP Snooping + DAI (Dynamic ARP Inspection) : Le switch vérifie la cohérence IP/MAC de chaque paquet.

VLAN & Trunking (802.1Q)

Le problème du domaine de broadcast unique

Un domaine de broadcast est l'espace logique d'un réseau informatique où n'importe quelle machine peut directement communiquer avec toutes les autres du même domaine, sans devoir passer par un routeur. C'est l'ensemble des machines qui recevront une trame de broadcast envoyée par l'une d'entre elles.

Sur un grand site, avoir 500 PC dans le même réseau physique crée un domaine de broadcast immense. Chaque requête ARP, chaque DHCP Discover, chaque annonce NetBIOS est envoyée à toutes les 500 machines. Résultat : le réseau est saturé par du trafic inutile (le "bruit de fond réseau"). Les VLANs permettent de scinder logiquement le switch en plusieurs switches virtuels indépendants.

Pourquoi créer des VLANs (Réseaux Virtuels) ?

  • Segmentation du broadcast : Chaque VLAN est un domaine de broadcast indépendant. Le broadcast du VLAN 10 ne sera jamais vu par les machines du VLAN 20.
  • Sécurité : Le VLAN 10 (Compta) ne peut pas communiquer avec le VLAN 20 (Invités) sans passer par un pare-feu ou un routeur qui applique des règles de filtrage. Même si les deux VLANs sont physiquement sur le même switch, ils sont logiquement aussi isolés que s'ils étaient sur deux switches dans deux bâtiments différents.
  • Qualité de Service (QoS) : On isole les téléphones IP dans un "VLAN Voix" prioritaire pour éviter que les téléchargements des PC ne hachent les appels (gigue, latence).
  • Flexibilité administrative : On peut déplacer un PC dans un autre bureau et le garder dans le même VLAN simplement en reconfigurant le port du switch, sans aucune modification de câblage.
  • Conformité réglementaire : Isoler les données sensibles (ex: données RH, données financières) dans des VLANs dédiés est souvent exigé par les audits de sécurité.

Configuration d'un VLAN

Chaque port du switch est assigné à un VLAN (le "port access VLAN"). Par défaut, tous les ports appartiennent au VLAN 1. L'administrateur crée des VLANs (ex: VLAN 10 "Agents", VLAN 20 "Invités", VLAN 30 "Voix") et assigne les ports en conséquence.

La liaison Trunk et le Tagging

Si on a deux switches séparés et que le VLAN 10 existe sur les deux, comment faire passer le trafic de ce VLAN dans le seul câble qui relie les deux switches ? Et si le VLAN 20 doit aussi passer par ce même câble ?

On configure ce port en Trunk. Le switch utilise le protocole 802.1Q : il "ouvre" la trame Ethernet et y insère un Tag de 4 octets (contenant le numéro du VLAN, appelé VLAN ID, sur 12 bits, soit des valeurs de 0 à 4095) entre la MAC source et l'EtherType. Le switch de l'autre côté lit ce tag, sait dans quel VLAN placer la trame, retire le tag, et envoie la trame sur le bon port access.

Trame Ethernet SANS tag (sur un port Access) : [MAC Dst][MAC Src][EtherType][Payload][FCS] Trame Ethernet AVEC tag 802.1Q (sur un lien Trunk) : [MAC Dst][MAC Src][0x8100][Tag 4 oct][EtherType][Payload][FCS] └─ TPID ─┘└─ TCI ──┘ │ ┌─────────────┴──────────────┐ │ PCP (3 bits) : Priorité QoS │ │ DEI (1 bit) : Drop Eligible│ │ VID (12 bits): VLAN ID │ └─────────────────────────────┘

Détail du Tag 802.1Q :

  • TPID (Tag Protocol Identifier) : Toujours 0x8100. C'est ce qui permet au switch récepteur de savoir qu'un tag est présent.
  • PCP (Priority Code Point) : 3 bits pour la priorité QoS (0 = basse, 7 = haute). Utilisé pour prioriser la voix sur les données.
  • DEI (Drop Eligible Indicator) : 1 bit indiquant si la trame peut être supprimée en cas de congestion.
  • VID (VLAN ID) : 12 bits pour l'identifiant du VLAN (0 à 4095). Le VLAN 0 est réservé, le VLAN 4095 est réservé. Il reste 4094 VLANs utilisables.
💡

Notion de terrain : Le VLAN Natif
Sur un lien Trunk, le trafic d'un VLAN spécifique (généralement le VLAN 1, ou un VLAN de management configuré par l'admin) n'est pas tagué. Si un PC se branche par erreur sur un lien Trunk, il tombera dans ce VLAN natif. Bonne pratique de sécurité : Changer le VLAN natif pour un VLAN inutilisé et vide (ex: VLAN 999) afin d'empêcher un accès accidentel ou malveillant au réseau.

Inter-VLAN Routing

Deux VLANs ne peuvent pas communiquer entre eux sans un routeur ou un switch L3. C'est le principe de l'inter-VLAN routing. À la DGFiP, cette fonction est assurée par le cœur de réseau (switch L3) qui possède une interface virtuelle (SVI — Switch Virtual Interface) dans chaque VLAN, servant de passerelle par défaut pour les machines de ce VLAN.

Spanning Tree Protocol (STP / 802.1D)

Le cauchemar des boucles réseau

Pour des raisons de redondance (haute disponibilité), on relie souvent les switches entre eux avec plusieurs câbles physiques. Si un câble ou un switch tombe en panne, le trafic passe par l'autre chemin. Le problème ? Sans mécanisme de protection, les trames de broadcast vont tourner en boucle à l'infini, se multiplier exponentiellement à chaque passage dans un switch, et saturer tous les liens à 100% en quelques secondes : c'est la tempête de broadcast (Broadcast Storm).

Sur le terrain, cela se voit immédiatement : tous les voyants des switches clignotent frénétiquement en continu, les serveurs deviennent inaccessibles, et plus rien ne répond. Le réseau entier est paralysé. C'est l'une des pannes réseau les plus redoutées et les plus spectaculaires.

Comment naît une tempête de broadcast : ┌────────────────────────────────────────────────────┐ │ PC1 envoie un broadcast (ex: ARP "Qui a 10.0.0.5 ?") │ │ │ │ Sw1 ──────► Sw2 ──────► Sw3 ──────► Sw1 ───(boucle !) │ │ ↑ │ │ │ │ │ └───────────┴───────────┴───────────┘ │ │ │ │ La trame tourne indéfiniment, et à chaque tour │ │ elle est dupliquée sur tous les ports de chaque │ │ switch → saturation exponentielle en < 5 sec ! │ └────────────────────────────────────────────────────┘

La solution : STP

STP sacrifie logiquement un lien physique pour casser la boucle, tout en gardant ce lien prêt à prendre le relais en cas de panne. Les switches s'envoient des paquets de diagnostic appelés BPDU (Bridge Protocol Data Units) toutes les 2 secondes sur l'adresse multicast réservée 01:80:c2:00:00:00.

Fonctionnement en 4 phases

  1. Élection du Root Bridge (Le Chef) : Chaque switch possède un Bridge ID composé d'une priorité (par défaut 32768) et de son adresse MAC. Le switch avec le Bridge ID le plus bas gagne l'élection et devient Root Bridge. S'il y a égalité de priorité, c'est la MAC la plus petite qui gagne. (Bonne pratique : forcer manuellement le switch cœur de réseau à être Root en lui donnant la priorité la plus basse, ex: 4096 ou 8192).
  2. Détermination du Root Port (RP) sur chaque switch : Sur chaque switch non-Root, le port qui offre le chemin le plus "rapide" (en coût de bande passante) pour joindre le Root Bridge devient le Root Port. Si plusieurs ports ont le même coût, c'est celui avec le plus petit port ID qui gagne.
  3. Détermination du Designated Port (DP) sur chaque segment : Sur chaque lien inter-switches, le port qui offre le meilleur chemin vers le Root est élu Designated Port. C'est le seul port autorisé à envoyer des trames sur ce segment.
  4. Blocage des ports restants : Tous les ports qui ne sont ni Root ni Designated sont mis en état Blocking. Ils n'envoient plus de données, mais continuent d'écouter les BPDU. Si le lien principal est coupé (par un tractopelle ou une panne de switch), le port bloqué détecte l'absence de BPDU et se "réveille" en passant par Listening → Learning → Forwarding.

Le problème du STP classique et ses évolutions

Le vieux STP (802.1D) met environ 30 à 50 secondes à recalculer son arbre en cas de panne (15 sec en Listening + 15 sec en Learning avant le Forwarding). Pendant ce temps, le réseau est coupé pour les utilisateurs — un temps d'interruption inacceptable dans un environnement de production.

PARTIE 3

Internet Protocol v4 (IPv4)

Principes IPv4

La version actuelle d'Internet est basée sur TCP/IP v4, décrite dans les RFC fondatrices datant de septembre 1981 : RFC 791 (IP), RFC 792 (ICMP) et RFC 793 (TCP). Une version v6 est en cours de déploiement progressif.

L'histoire : D'ARPANET à Internet

ARPANET (Advanced Research Projects Agency Network) a été le premier réseau à utiliser la commutation de paquets, ancêtre d'Internet. Créé en 1969 par la DARPA (agence du Département de la Défense américain), il connectait initialement 4 universités américaines. En 1983, ARPANET adopte officiellement le protocole TCP/IP, marquant la naissance technique d'Internet. Le réseau s'est ensuite ouvert au grand public dans les années 1990 avec l'invention du Web (HTTP/HTML) par Tim Berners-Lee au CERN.

RFC (Request For Comments)

Les RFC sont une série de documents décrivant les spécifications techniques d'Internet, publiés par l'IETF (Internet Engineering Task Force). Peu sont des standards formels, mais tous les documents publiés par l'IETF sont des RFC. Toute modification entraîne une nouvelle RFC qui rend la précédente obsolète — les RFC ne sont jamais modifiées après publication.

Processus RFC :

  1. Quelqu'un publie une idée sous forme de RFC Draft (brouillon).
  2. La communauté (ingénieurs, entreprises, chercheurs) commente, teste, critique.
  3. Si l'idée est digne d'intérêt, elle est acceptée et publiée avec un numéro définitif.
  4. Si elle est rejetée ou modifiée, une nouvelle RFC est créée rendant la précédente obsolète.

Exemples de RFC célèbres : RFC 791 (IPv4), RFC 2616 (HTTP/1.1 — obsolète), RFC 7230-7235 (HTTP/1.1 actuel), RFC 8446 (TLS 1.3), RFC 2119 ("MUST", "SHOULD"...), RFC 1149 (Transmission de paquets IP par pigeons voyageurs — publié le 1er avril 1990, un poisson d'avril de l'IETF !).

Adressage IPv4

  • 4 octets de 8 bits = 32 bits au total
  • Chaque octet : valeur de 0 à 255 (en décimal) ou 00 à FF (en hexadécimal)
  • Total possible : 2³² = 4 294 967 296 adresses (environ 4,3 milliards)
  • Notation : quatre entiers décimaux séparés par des points : 192.168.1.0

Note technique : C'est précisément cette limite d'environ 4,3 milliards d'adresses, aujourd'hui totalement épuisées face à la multiplication des smartphones et objets connectés (IoT — caméras, montres connectées, réfrigérateurs...), qui a rendu obligatoire la création et la transition vers IPv6 (qui offre 2¹²⁸ = 340 sextillions d'adresses, soit environ 667 millions de milliards d'adresses par mm² de surface terrestre !).

Réseau vs Sous-réseau : une nuance terminologique

Les notions de réseau et de sous-réseau sont équivalentes en pratique. À part l'ensemble complet du réseau IP (0.0.0.0/0), tout réseau est le sous-réseau d'un réseau plus grand. Un /24 est un sous-réseau d'un /16, qui est lui-même un sous-réseau d'un /8. Dans ce cours et dans la vie professionnelle, les deux termes sont utilisés de manière interchangeable.

Conversion Décimal ↔ Binaire (La base du subnetting)

Pour maîtriser les masques de sous-réseau et le subnetting, il est indispensable de savoir convertir rapidement entre décimal et binaire. Chaque octet correspond à 8 bits avec les valeurs suivantes :

Position : 7 6 5 4 3 2 1 0 Valeur : 128 64 32 16 8 4 2 1 Exemple : 192 en binaire ? 192 = 128 + 64 = 11000000 Exemple : 255 en binaire ? 255 = 128+64+32+16+8+4+2+1 = 11111111 Exemple : 10101100 en décimal ? = 128 + 32 + 8 + 4 = 172

192.168.286.3 est une adresse invalide (3ème octet 286 > 255). Chaque octet doit être compris entre 0 et 255 inclus.

Masque de sous-réseau, adresse de réseau et broadcast

Une adresse IP seule ne signifie rien. Elle est toujours associée à un masque de sous-réseau (32 bits) qui indique quelle partie de l'adresse identifie le réseau et quelle partie identifie la machine au sein de ce réseau.

  • Série de 1 contigus (bits réseau) suivie d'une série de 0 contigus (bits machine). Il ne peut jamais y avoir de 0 au milieu des 1.
  • Deux notations : IPv4 classique (255.255.255.0) ou CIDR (/24 — le nombre après le slash indique le nombre de bits à 1).

Plus le masque est grand (ex: /28 au lieu de /24), plus on a de réseaux possibles mais moins de machines dans chaque réseau. Inversement, un masque petit (ex: /8) offre énormément de machines mais peu de réseaux distincts.

L'opération ET logique (AND)

Techniquement, l'ordinateur utilise une opération mathématique appelée "ET Logique" (AND) entre son adresse IP et son masque pour déterminer son adresse de réseau. Ensuite, il fait la même opération avec l'adresse IP de destination :

  • Si les deux résultats sont identiques → la destination est sur le même réseau local → le PC peut parler directement à la machine (après résolution ARP).
  • Si les résultats sont différents → la destination est sur un autre réseau → le PC envoie son paquet à la passerelle par défaut (le routeur).

Règles du ET logique : 1 AND 1 = 1, 1 AND 0 = 0, 0 AND 1 = 0, 0 AND 0 = 0.

Calcul des adresses

  • Adresse de réseau = IP AND masque → tous les bits "host" sont mis à zéro. C'est la première adresse du réseau, elle identifie le réseau lui-même et ne peut pas être attribuée à une machine.
  • Adresse de broadcast = tous les bits "host" mis à un. C'est la dernière adresse du réseau, elle sert à envoyer un message à toutes les machines du réseau. Ne peut pas non plus être attribuée à une machine.
  • Plage d'adresses utilisables = entre (adresse réseau + 1) et (adresse broadcast − 1)
  • Nombre de machines = 2(nombre de bits host) − 2 (on retire l'adresse réseau et le broadcast)

Exemple détaillé pas à pas

IP/masque : 192.168.1.130 / 255.255.255.192 (soit /26)

Étape 1 — Conversion en binaire :

IP : 11000000.10101000.00000001.10|000010 Masque : 11111111.11111111.11111111.11|000000 ↑ Frontière réseau/host 26 bits réseau | 6 bits host

Étape 2 — ET logique (bits host à zéro) :

Adresse réseau : 192.168.1.128 (les 6 bits host sont mis à 0 → 10|000000 = 128)

Étape 3 — Broadcast (bits host à un) :

Adresse broadcast : 192.168.1.191 (les 6 bits host sont mis à 1 → 10|111111 = 191)

Étape 4 — Plage et nombre de machines :

Plage : 192.168.1.129 à 192.168.1.190 → 2⁶ − 2 = 62 machines

IP/masque : 192.168.1.0 / 24

Adresse réseau : 192.168.1.0 | Broadcast : 192.168.1.255

VLSM / Subnetting / Supernetting

L'abandon des classes (CIDR, RFC 4632) permet de découper avec une granularité totale (toutes les valeurs CIDR de /0 à /32 sont possibles). C'est le principe du VLSM (Variable Length Subnet Mask) : chaque sous-réseau peut avoir un masque différent, adapté exactement au nombre de machines nécessaires.

Cas particuliers

  • /32 : une adresse IP unique, indépendamment du réseau. Très utilisé dans les règles de pare-feu pour cibler une machine précise, ou dans les interfaces loopback des routeurs.
  • /31 : la RFC 3021 permet d'utiliser ce masque pour les liens point-à-point entre deux routeurs. Pas d'adresse de broadcast ni de sous-réseau (les deux adresses sont utilisables). Cela permet d'économiser 2 adresses IP à chaque fois que l'on relie deux routeurs entre eux — sur un réseau de milliers de routeurs, l'économie est significative.
  • /30 : le plus petit réseau "classique" utilisable (4 adresses dont 2 utilisables). Historiquement utilisé pour les liens point-à-point avant la RFC 3021.

Subnetting (Découpage en sous-réseaux)

Découper un réseau en sous-réseaux plus petits. Le découpage se fait toujours en deux parties égales (on ajoute un bit au masque à chaque découpage). Les découpages asymétriques sont interdits car ils violeraient le principe de contiguïté des bits du masque.

Exemple de subnetting

Réseau de départ : 192.168.1.0/24 (254 machines)

1er découpage (/24 → /25) : On ajoute 1 bit au masque

  • 192.168.1.0/25 → machines .1 à .126 (126 machines)
  • 192.168.1.128/25 → machines .129 à .254 (126 machines)

2ème découpage du 2nd sous-réseau (/25 → /26) :

  • 192.168.1.128/26 → machines .129 à .190 (62 machines)
  • 192.168.1.192/26 → machines .193 à .254 (62 machines)

On obtient 3 sous-réseaux : un /25 et deux /26 — c'est du VLSM.

Supernetting (Agrégation de routes)

L'opération inverse du subnetting : regrouper plusieurs sous-réseaux contigus pour former un réseau plus grand. On retire un bit au masque. Principalement utilisé par les FAI pour simplifier leurs tables de routage (agrégation de routes ou route summarization).

Exemple : Un FAI possède les 4 réseaux 192.168.0.0/24, 192.168.1.0/24, 192.168.2.0/24 et 192.168.3.0/24. Au lieu d'annoncer 4 routes à ses voisins BGP, il les regroupe en une seule : 192.168.0.0/22. Cela réduit la taille des tables de routage Internet (qui contiennent plus de 950 000 routes en 2024).

ICMP (Internet Control Message Protocol)

ICMP (RFC 792) est le protocole de signalisation et de diagnostic de la couche réseau. Contrairement à TCP ou UDP, ICMP ne transporte pas de données applicatives — il sert au fonctionnement interne du réseau :

  • Destination Unreachable (Type 3) : Un datagramme ne peut pas atteindre sa destination. Plusieurs codes précisent la raison : réseau inaccessible (code 0), hôte inaccessible (code 1), protocole inaccessible (code 2), port inaccessible (code 3), fragmentation nécessaire mais DF activé (code 4).
  • Time Exceeded (Type 11) : Le TTL du paquet a atteint 0. Le routeur détruit le paquet et renvoie cette erreur. C'est le mécanisme exploité par traceroute.
  • Redirect (Type 5) : Un routeur informe l'émetteur qu'il existe une meilleure route pour cette destination.
  • Source Quench (Type 4) : Ancien mécanisme de contrôle de congestion (le routeur demande à l'émetteur de ralentir). Obsolète et ignoré par les systèmes modernes.
  • Echo Request (Type 8) / Echo Reply (Type 0) : Utilisés par la commande ping. L'émetteur envoie un Echo Request, le destinataire répond par un Echo Reply. Si le Reply revient, la connectivité IP fonctionne.

La commande ping en détail

# Ping avec paramètres avancés

ping -n 4 10.154.96.38              # Windows : envoyer seulement 4 paquets

Traceroute / Tracepath — Cartographie du réseau

traceroute (Linux) ou tracert (Windows) exploite le champ TTL en l'augmentant de 1 à chaque saut pour forcer les routeurs à répondre :

  1. L'émetteur envoie un paquet avec TTL = 1.
  2. Le premier routeur reçoit le paquet, décrémente le TTL à 0, détruit le paquet et renvoie un ICMP "Time Exceeded" — révélant son adresse IP.
  3. L'émetteur envoie un paquet avec TTL = 2.
  4. Le premier routeur le laisse passer (TTL passe à 1). Le deuxième routeur le reçoit, TTL = 0, détruit et répond → révèle son IP.
  5. Et ainsi de suite jusqu'à atteindre la destination (qui répond par un Echo Reply ou un Port Unreachable).

Note : Certains routeurs sont configurés pour ne pas répondre aux requêtes ICMP (ils apparaissent comme * * * dans le traceroute). C'est une mesure de sécurité pour masquer l'infrastructure interne.

tracepath si.intranet.dgfip        # Linux : trace + détection PMTU
tracert -d si.intranet.dgfip        # Windows : -d = ne pas résoudre les noms (plus rapide)bash

MSS (Maximum Segment Size)

Le MSS est la taille maximale de données TCP que l'on peut envoyer dans un seul segment, sans fragmentation. Il est négocié lors du 3-way handshake TCP via l'option TCP MSS.

MSS = MTU − en-tête IP (20 oct.) − en-tête TCP (20 oct.) = MTU − 40.

Exemple : Sur un lien Ethernet standard (MTU=1500), le MSS est de 1460 octets. Sur un lien PPPoE (MTU=1492), le MSS tombe à 1452 octets.

Sous Linux, on peut utiliser tracepath <destination> pour découvrir le PMTU (Path MTU) — le MTU le plus petit sur tout le chemin entre la source et la destination. Ce PMTU peut varier dans le temps (suite à un reroutage) et être asymétrique (différent dans les deux sens).

⚠️

Le problème du "Trou Noir" (PMTU Black Hole) : Si un paquet de 1500 octets arrive sur un lien PPPoE (1492 octets) et que le bit "Don't Fragment" (DF) est activé (c'est le cas par défaut sur la plupart des systèmes), le routeur ne peut pas fragmenter le paquet. Il le détruit et renvoie un message ICMP "Fragmentation Needed" (Type 3, Code 4). Si un pare-feu mal configuré bloque l'ICMP (erreur fréquente !), l'émetteur ne sera jamais prévenu : la connexion plantera silencieusement sur les gros transferts (téléchargement de fichiers), tandis que les petites requêtes (ping) fonctionneront normalement. C'est l'un des problèmes réseau les plus difficiles à diagnostiquer.

ARP (Address Resolution Protocol)

ARP (RFC 826) permet de récupérer l'adresse MAC d'une machine dont l'adresse IP est connue, sur le même réseau local. C'est la passerelle indispensable entre la Couche 3 (IP) et la Couche 2 (MAC).

Pourquoi est-ce nécessaire ? L'adresse IP permet de trouver le bon réseau et le bon hôte, mais pour envoyer concrètement le signal électrique sur le câble via le switch, la carte réseau a absolument besoin de connaître l'adresse physique (MAC) de la cible. Le switch ne comprend pas les adresses IP — il ne travaille qu'avec des adresses MAC.

Fonctionnement détaillé

  1. Vérification du cache ARP : L'émetteur vérifie son cache ARP (table locale en RAM). Si l'adresse IP demandée est trouvée avec une MAC associée → il l'utilise directement. Pas de requête réseau nécessaire.
  2. Requête ARP en broadcast : Sinon, il construit un paquet ARP Request avec :
    • MAC Source : sa propre adresse MAC
    • MAC Destination : ff:ff:ff:ff:ff:ff (broadcast — tout le monde sur le LAN va recevoir cette trame)
    • Contenu : « Qui possède l'adresse IP x.x.x.x ? Je suis [MAC émetteur] à l'IP [IP émetteur]. »
    Cette requête broadcast inonde tous les ports du switch dans le même VLAN, d'où l'importance de créer des VLANs pour limiter ces tempêtes de broadcast.
  3. Réponse ARP en unicast : La station qui reconnaît son IP comme étant la sienne répond avec son adresse MAC directement à l'émetteur (unicast — seul l'émetteur reçoit la réponse). Elle met aussi à jour son propre cache ARP avec les adresses IP et MAC de l'émetteur (optimisation : puisqu'on va probablement communiquer, autant mettre à jour les deux caches).
  4. Mise à jour du cache : L'émetteur met à jour son cache et peut maintenant construire la trame Ethernet avec la bonne MAC de destination et envoyer le paquet IP.

ARP Spoofing (Empoisonnement ARP)

Attaque consistant à envoyer de fausses réponses ARP pour empoisonner le cache ARP des victimes et intercepter le trafic (attaque Man-in-the-Middle).

Scénario d'attaque :

  1. L'attaquant envoie un GARP aux machines du réseau : "L'IP de la passerelle (10.0.0.1) correspond à MA propre MAC."
  2. Les victimes mettent à jour leur cache ARP avec la fausse information.
  3. Tout le trafic destiné à la passerelle (Internet, serveurs) est maintenant envoyé à l'attaquant.
  4. L'attaquant lit le trafic (mots de passe, données...) puis le retransmet à la vraie passerelle pour ne pas couper la connexion et rester invisible.

Parades techniques :

  • DAI (Dynamic ARP Inspection) sur les switches : le switch surveille les requêtes ARP et bloque tout port qui ment sur son identité IP/MAC en comparant avec la base DHCP Snooping.
  • Entrées ARP statiques pour les équipements critiques (passerelle, serveurs).
  • 802.1X pour authentifier chaque machine sur le réseau.
  • Chiffrement (HTTPS, SSH, VPN) pour que même si le trafic est intercepté, il soit illisible.

NAT (Network Address Translation)

Du fait du manque d'adresses IPv4 publiques, le NAT permet de n'exposer qu'une seule adresse publique à l'extérieur pour des centaines ou des milliers de machines internes utilisant des adresses privées. C'est le NAT qui a "sauvé" IPv4 de l'épuisement total dans les années 90. Cependant, il casse le principe de bout-en-bout d'Internet (ce qu'IPv6 restaure en donnant une IP unique à chaque appareil).

Le NAT peut fonctionner de deux façons fondamentalement différentes :

NAT Statique vs NAT Dynamique

  • NAT Statique : Le routeur remplace l'adresse privée d'une machine par une adresse publique fixe et dédiée, obtenue auprès du FAI. Chaque machine interne a sa propre IP publique. Coûteux en adresses IP, utilisé uniquement pour les serveurs qui doivent être accessibles de l'extérieur.
  • NAT Dynamique (PAT / MASQUERADE) : Plusieurs machines internes partagent une seule adresse IP publique. Le routeur utilise les numéros de port TCP/UDP pour distinguer les différentes machines et sessions. C'est le mode le plus courant (votre Box Internet fonctionne ainsi).

SNAT (Source NAT / MASQUERADE)

Remplace l'adresse privée source par l'adresse publique du routeur pour les paquets sortants.

Fonctionnement détaillé du PAT (Port Address Translation) :

  1. Le PC interne 192.168.1.10:45000 ouvre une page web vers 93.184.216.34:80.
  2. Le routeur NAT reçoit le paquet. Il remplace l'IP source par son IP publique (87.1.2.3) et invente un port source éphémère (50001).
  3. Le routeur inscrit dans sa Table NAT : 192.168.1.10:45000 ↔ 87.1.2.3:50001 → 93.184.216.34:80
  4. Le serveur web reçoit le paquet de 87.1.2.3:50001, répond normalement.
  5. Quand la réponse revient sur le port 50001, le routeur consulte sa table NAT et sait qu'il doit renvoyer le paquet au PC 192.168.1.10:45000.

Problème potentiel : Si deux PC internes utilisent par hasard le même port source (ex: les deux en 45000), le routeur attribue un port éphémère différent à chacun (ex: 50001 et 50002) pour les distinguer.

DNAT (Destination NAT / Port Forwarding)

Change l'adresse de destination pour rediriger le trafic entrant vers un serveur interne. C'est le mécanisme du port forwarding (redirection de port).

  • Le client extérieur ne connaît que l'adresse publique du routeur.
  • Le routeur modifie la destination selon le port. Exemple : Tout ce qui arrive sur l'IP publique 87.1.2.3:443 (HTTPS) est redirigé vers le serveur interne 192.168.1.50:443.
  • Le routeur peut aussi changer le port de destination (ex: trafic entrant sur le port 8080 redirigé vers le port 80 interne).
  • Protège le reste du réseau interne (seul le serveur ciblé est accessible).

Routage

Le routage est un mécanisme qui détermine le chemin que doivent suivre les paquets pour arriver à destination. Il fonctionne pas à pas (hop by hop) : chaque routeur consulte sa table de routage et transmet au voisin suivant. Il n'y a aucune connaissance globale du réseau — un routeur ne connaît que le prochain saut, pas la destination finale ni le chemin complet.

Un équipement assurant la fonction de routage doit prendre en charge le réacheminement des paquets qui ne lui sont pas destinés. La gestion du flux et des erreurs est repoussée aux extrémités grâce à TCP. Une machine ordinaire (Linux ou Windows) peut se comporter comme un routeur (en activant l'IP Forwarding via sysctl net.ipv4.ip_forward=1 sous Linux).

Table de routage et Règle du Longest Prefix Match

Chaque machine (pas seulement les routeurs — votre PC possède aussi une table de routage !) en possède une. La consultation suit la règle du masque le plus long au plus petit (Longest Prefix Match). Le routeur choisira toujours la route la plus précise : un masque /24 l'emportera toujours sur un masque /8 si les deux correspondent.

Algorithme de consultation :
  1. Pour chaque ligne de la table (en partant du masque le plus long) : effectuer un ET logique entre l'IP destination du paquet et le masque de la ligne.
  2. Si le résultat = l'adresse réseau de la ligne → cette route est candidate.
  3. Parmi toutes les routes candidates, celle avec le masque le plus long gagne.
  4. Le paquet est envoyé à la passerelle (gateway) indiquée dans la route gagnante. S'il n'y a pas de passerelle (champ vide ou —), le paquet est envoyé directement sur l'interface.

Analyse détaillée :

Protocoles de routage dynamique courants :

  • OSPF (Open Shortest Path First) : Protocole à état de lien. Chaque routeur connaît la topologie complète de sa zone et calcule le chemin le plus court (algorithme de Dijkstra). Standard ouvert, très utilisé en réseau d'entreprise et au sein du RIE.
  • BGP (Border Gateway Protocol) : Le protocole qui fait fonctionner Internet. Utilisé entre les opérateurs (Systèmes Autonomes — AS) pour échanger les routes. La table BGP mondiale contient plus de 950 000 routes en 2024.
  • RIP (Routing Information Protocol) : Ancien protocole simple basé sur le nombre de sauts (max 15). Obsolète dans les réseaux modernes.
  • EIGRP (Enhanced Interior Gateway Routing Protocol) : Protocole Cisco propriétaire, hybride entre vecteur de distance et état de lien.

Adresses MAC en routage (Le changement à chaque saut)

C'est un concept fondamental souvent mal compris :

  • Les adresses IP (Couche 3) restent identiques tout le long du chemin (sauf s'il y a du NAT).
  • Les adresses MAC (Couche 2) changent à chaque tronçon (remplacement par la MAC du routeur suivant).

Explication physique : Le routeur détruit la trame Ethernet entrante, lit l'adresse IP de destination dans le paquet, consulte sa table de routage, puis recrée une toute nouvelle trame avec une nouvelle MAC source (la sienne, sur l'interface de sortie) et une nouvelle MAC destination (celle du prochain routeur, obtenue par ARP). Le support physique peut même changer (cuivre en entrée, fibre en sortie).

PARTIE 5

Couche Transport

TCP (Transmission Control Protocol)

La couche Transport (Couche 4) est le lien entre le réseau matériel (qui achemine les paquets de façon "best effort") et les applications logicielles (qui ont besoin de fiabilité). L'unité de donnée (PDU) de TCP s'appelle un Segment.

  • Introduit la notion de port TCP (un entier entre 0 et 65535)
  • Transport fiable : retransmission automatique des données erronées ou non reçues
  • Mode connecté (session établie avant l'envoi), ordonné (les données arrivent dans l'ordre) et bi-directionnel (full-duplex)
  • Contrôle de flux (sliding window) et contrôle de congestion (slow start, congestion avoidance)
  • Usages : HTTP, HTTPS, FTP, SSH, SMTP, SMB, IMAP… — tout ce qui nécessite la fiabilité

Note technique : TCP garantit que les données arrivent dans l'ordre exact où elles ont été envoyées. Si un routeur inverse deux paquets en chemin (ce qui arrive fréquemment sur Internet), la couche TCP du récepteur les remettra dans le bon ordre grâce aux numéros de séquence avant de les donner à l'application.

Ports TCP et Multiplexage

Le couple IP + Port = Socket TCP (ex: 192.168.1.10:443). C'est grâce aux ports (le multiplexage) qu'un ordinateur avec une seule adresse IP peut naviguer sur 10 sites web différents en même temps sans mélanger les pages. Chaque connexion est identifiée de façon unique par un quadruplé : (IP source, Port source, IP destination, Port destination).

Ouverture de session (3-way handshake)

Avant d'envoyer la moindre donnée utile, TCP s'assure que le destinataire est prêt à l'écouter. C'est la poignée de main en 3 temps :

  1. Client → Serveur : Paquet avec drapeau SYN (Synchronize). Le client choisit un numéro de séquence initial aléatoire (ISN — Initial Sequence Number, ex: SEQ=1000).
  2. Serveur → Client : Paquet avec drapeaux SYN + ACK (Acknowledge). Le serveur choisit son propre ISN (ex: SEQ=5000) et confirme avoir reçu le SYN du client (ACK=1001).
  3. Client → Serveur : Paquet avec drapeau ACK (ACK=5001). La session est ouverte, les données peuvent circuler.

Cybersécurité : L'attaque SYN Flood (DDoS)
L'attaquant envoie des millions de paquets SYN avec des adresses IP sources falsifiées (spoofées), mais ne répond jamais le dernier ACK. Le serveur garde des millions de sessions "à moitié ouvertes" (half-open) en RAM, chacune consommant de la mémoire. Quand la table des connexions est pleine, le serveur ne peut plus accepter aucune nouvelle connexion légitime → Déni de Service.

Parades :
① SYN Cookies : Le serveur encode les informations de la connexion dans le numéro de séquence du SYN+ACK, sans allouer de mémoire. La mémoire n'est allouée que si le client répond avec un ACK valide.
② Pare-feux Stateful : Détectent et bloquent les flux de SYN anormaux.
③ Rate limiting : Limiter le nombre de nouvelles connexions par seconde par IP source.

Fermeture de session (4-way teardown)

TCP est poli — il ferme la connexion proprement pour s'assurer qu'aucune donnée n'est perdue en route :

  1. Machine A → B : drapeau FIN ("J'ai fini d'envoyer mes données")
  2. Machine B → A : ACK ("Bien reçu, je termine de t'envoyer mes dernières données")
  3. Machine B → A : FIN ("Moi aussi j'ai fini")
  4. Machine A → B : ACK ("OK, au revoir") → Session close. Machine A entre en état TIME_WAIT pendant 2×MSL (Maximum Segment Lifetime, typiquement 60 secondes) pour absorber les segments retardataires.

Note : Si une machine plante ou qu'un pare-feu coupe brutalement la connexion, un paquet avec le drapeau RST (Reset) est envoyé. La connexion est détruite instantanément sans préavis — les données en transit sont perdues.

Numéros de séquence (SEQ) et d'acquittement (ACK)

L'expéditeur utilise des SEQ pour numéroter chaque octet envoyé (pas chaque paquet — chaque octet). Le récepteur envoie des ACK indiquant le prochain octet qu'il attend. Si un segment manque (ex: le routeur a détruit le paquet à cause d'un FCS faux), le récepteur continue d'envoyer le même ACK (Duplicate ACK). Après 3 ACK dupliqués, l'émetteur retransmet immédiatement le segment manquant sans attendre le timeout (Fast Retransmit).

Fenêtre glissante (Sliding Window)

Envoyer un ACK à chaque paquet n'est pas efficace (cela ralentirait énormément le débit). La fenêtre indique le nombre maximum d'octets transmissibles avant de devoir recevoir un ACK. C'est un mécanisme de contrôle de flux :

  • Le récepteur annonce sa fenêtre de réception (rwnd) dans chaque ACK — c'est l'espace libre dans son buffer.
  • L'émetteur ne doit jamais envoyer plus d'octets que ce que le récepteur peut absorber.
  • Si le récepteur est lent (buffer plein), il envoie une fenêtre de 0 → l'émetteur s'arrête (Zero Window).
  • Si une erreur survient, les paquets depuis le dernier ACK devront être retransmis.

Évolution : Sur les réseaux modernes à très haut débit (Fibre, 10 Gbps), la fenêtre standard de 64 Ko (16 bits dans l'en-tête TCP) est trop petite. On utilise l'option TCP Window Scaling (RFC 7323) pour l'agrandir jusqu'à 1 Go, permettant de saturer les liens à haut débit sans attendre les accusés de réception en permanence.

Contrôle de congestion TCP

En plus du contrôle de flux (adapté au récepteur), TCP gère le contrôle de congestion (adapté au réseau) :

  • Slow Start : L'émetteur commence avec une petite fenêtre de congestion (cwnd = 1 segment) et la double à chaque RTT (Round-Trip Time) — croissance exponentielle.
  • Congestion Avoidance : Quand cwnd atteint un seuil (ssthresh), la croissance devient linéaire (+1 segment par RTT) pour éviter de saturer le réseau.
  • Fast Recovery : En cas de perte (3 ACK dupliqués), cwnd est réduite de moitié (au lieu de repartir à 1 comme dans le Slow Start classique), ce qui permet une récupération plus rapide.

Algorithmes modernes : CUBIC (Linux par défaut), BBR (Google, utilisé sur YouTube et Google Cloud), DCTCP (optimisé pour les Datacenters).

UDP (User Datagram Protocol)

L'unité de donnée (PDU) d'UDP s'appelle un Datagramme. Sa philosophie est le "Fire and Forget" (Tire et oublie).

  • Port UDP (0 à 65535), totalement indépendant de TCP. Le port TCP 53 et le port UDP 53 sont deux portes totalement différentes sur la même machine.
  • Traitement minimal, mode non connecté (pas de 3-way handshake — on envoie la donnée directement).
  • Pas d'accusé de réception, pas de contrôle de flux, pas de réémission, pas de numéro de séquence.
  • En-tête ultra léger : seulement 8 octets (contre 20 minimum pour TCP).
  • Usages : DNS, DHCP, SNMP, VoIP (RTP), jeux vidéo en ligne, streaming vidéo, TFTP…

UDP préfère perdre une donnée plutôt que de créer du lag. De plus, le broadcast et le multicast ne fonctionnent qu'en UDP (pas de handshake possible avec "tout le monde à la fois").

Couches hautes — Protocoles applicatifs

DHCP (Dynamic Host Configuration Protocol)

Le DHCP (basé sur le Bootstrap Protocol — BootP) permet la configuration réseau automatique et centralisée des machines. Il intervient lors de la connexion d'une machine sur un réseau ou lors d'un renouvellement de bail. Son principal intérêt est d'éviter la configuration fixe et la gestion manuelle des adresses utilisées/libres.

Le protocole DHCP peut envoyer de nombreuses informations :

  • Adresse IP / Masque de sous-réseau
  • Passerelle par défaut (Option 3 — Router)
  • Serveurs DNS (Option 6)
  • Durée du bail (Option 51)
  • Nom de domaine (Option 15), Domaines de recherche
  • Routes statiques (Option 121), Nom NetBIOS (Windows)...

Note terrain : En entreprise, on utilise souvent la Réservation DHCP (Baux statiques). Le serveur DHCP lit l'adresse MAC de l'imprimante ou du serveur et lui donne toujours la même adresse IP. Cela centralise la gestion tout en garantissant une IP fixe — le meilleur des deux mondes.

Fonctionnement (DORA)

  1. DISCOVER : Le client émet en broadcast une demande d'adresse IP.
    • MAC Source : MAC du client
    • MAC Dest : FF:FF:FF:FF:FF:FF
    • IP Source : 0.0.0.0 (le client n'a pas encore d'IP)
    • IP Dest : 255.255.255.255 (broadcast limité)
    • Port Source : UDP 68 (client)
    • Port Dest : UDP 67 (serveur)
    Le champ "Client MAC Address" dans le payload DHCP contient l'adresse MAC du client — c'est grâce à ce champ que le serveur identifie le client et peut lui attribuer une réservation.
  2. OFFER : Le serveur DHCP (port UDP 67) propose une adresse IP disponible, avec le masque, la passerelle, les DNS, la durée du bail...
  3. REQUEST : Le client accepte l'offre et demande formellement l'utilisation de cette adresse. Ce message est en broadcast pour prévenir les éventuels autres serveurs DHCP qu'il a choisi cette offre (ils peuvent libérer les adresses proposées).
    • Optimisation : Le champ "Requested IP Address" (Option 50) contient souvent l'adresse précédemment utilisée — le client demande au serveur s'il peut la réutiliser.
  4. ACK : Le serveur accorde l'adresse IP pour la durée du bail. Ce message peut contenir tous les paramètres de configuration.

Renouvellement du bail

Le bail n'est pas éternel. À 50% de la durée du bail, le client tente de renouveler en envoyant un REQUEST directement au serveur (unicast). Si le serveur ne répond pas, le client réessaie à 87.5% du bail en broadcast. Si le bail expire sans renouvellement, le client perd son IP et doit recommencer tout le processus DORA.

DHCP National / DHCP Relay (DGFiP)

Le DHCP ne fonctionne que sur le réseau local (broadcast). Or, un routeur bloque techniquement tous les broadcasts pour éviter de saturer les réseaux adjacents et Internet.

Comment le serveur DHCP National (centralisé, situé à Paris ou Noisy) peut-il alors servir les postes d'un bureau à Toulouse ?

Le DHCP Relay (configuré sur le cœur de réseau local) écoute les broadcasts DHCP Discover, les transforme en paquets Unicast normaux, et les renvoie au serveur DHCP National. Le relay ajoute l'information du sous-réseau d'origine (champ GIADDR — Gateway IP Address) pour que le serveur sache dans quelle plage d'adresses piocher.

Sur les équipements Cisco, cette fonction s'active via la commande ip helper-address <IP du serveur DHCP> appliquée sur l'interface VLAN du routeur.

Attaques DHCP :
① DHCP Starvation : L'attaquant envoie des centaines de DHCP Discover avec des adresses MAC différentes (fausses). Le serveur épuise toute sa plage d'adresses → plus aucun PC légitime ne peut obtenir d'IP.
② Rogue DHCP (Serveur pirate) : L'attaquant met en place un faux serveur DHCP qui répond plus vite que le vrai. Il distribue sa propre adresse comme passerelle par défaut → tout le trafic transite par lui (Man-in-the-Middle).

Parade : DHCP Snooping — Le switch est configuré pour n'autoriser les réponses DHCP (OFFER, ACK) que sur les ports "trusted" (ceux reliés au cœur de réseau). Tout port "untrusted" (relié à un PC) qui tente d'envoyer une réponse DHCP est immédiatement bloqué.

Le domaine gouv.fr est soumis à des procédures spécifiques. La DGFiP obtient la délégation de la zone dgfip.finances.gouv.fr et maintient un serveur DNS pour délivrer les adresses de ses serveurs accessibles par le public.

Le concept de TTL (Time To Live) dans les enregistrements DNS

Chaque enregistrement DNS possède un TTL (ex: 3600 secondes = 1 heure). C'est le temps pendant lequel un client ou un serveur intermédiaire a le droit de garder la réponse en cache. Passé ce délai, il devra interroger à nouveau le serveur autoritaire.

Usage pratique : Pour migrer un site web vers un nouveau serveur sans coupure, l'administrateur doit baisser le TTL à 300s (5 min) plusieurs jours à l'avance. Ainsi, quand il changera l'IP, les anciens caches expireront rapidement et pointeront vers le nouveau serveur.

Parcours de résolution (Récursif vs Itératif)

Mode récursif (ascendant — recommandé) : Le client interroge son serveur DNS local (ex: ns1.dgfip = 10.156.32.33). Si ce serveur ne connaît pas la réponse, il fait le travail de recherche pour le client : il interroge les serveurs racine, puis le TLD, puis le domaine, et met en cache chaque réponse intermédiaire pour les futures requêtes. Le client reçoit la réponse finale directement.

Mode itératif (descendant — à proscrire côté client) : Le client interroge d'abord les serveurs racine, qui répondent "je ne sais pas, mais demande au serveur de .fr". Le client interroge alors le serveur de .fr, qui dit "demande au serveur de gouv.fr", etc. Cette méthode ignore les caches intermédiaires et génère beaucoup plus de trafic.

HTTP (HyperText Transfer Protocol)

Protocole requête/réponse : le client ouvre une connexion TCP (port 80 par défaut) et envoie une requête. Le serveur répond avec un code de statut et le contenu demandé.

Notion fondamentale : HTTP est un protocole "Stateless" (Sans état). Le serveur oublie le client dès la réponse envoyée. Pour maintenir une session (ex: rester connecté à un compte), on utilise des Cookies (stockés côté client et renvoyés à chaque requête) ou des Tokens JWT (JSON Web Tokens, très utilisés dans les API REST modernes).

Sécurité — HTTPS (HTTP + TLS)

HTTP circule en clair — identifiants, mots de passe, données personnelles sont lisibles par quiconque intercepte le trafic (démontré dans l'exercice DGFiP où les credentials "dgfip/bidon" envoyés en HTTP sont visibles en clair dans Wireshark). HTTPS ajoute une couche TLS (Transport Layer Security, port 443) :

  1. Le client initie une connexion TCP vers le port 443.
  2. Le TLS Handshake commence : le serveur envoie son certificat X.509 contenant sa clé publique, signé par une Autorité de Certification (CA).
  3. Le client vérifie le certificat : la chaîne de confiance (CA intermédiaire → CA racine), la date de validité, le nom de domaine (Subject Alternative Name).
  4. Si valide, client et serveur négocient une clé de session symétrique (via Diffie-Hellman ou ECDH) pour chiffrer la suite des échanges. Le chiffrement symétrique (AES-256-GCM) est beaucoup plus rapide que l'asymétrique.
  5. Toutes les données HTTP sont désormais chiffrées — un intercepteur ne voit que du bruit.

- AC Racine Finances Publiques (Autorité racine, installée dans le magasin de certificats de tous les postes DGFiP)
- AC_DGFIP_Serveur (CA intermédiaire, signe les certificats des serveurs internes)
- AC DGFIP Ressources (pour les certificats utilisateur/machine)

API REST

Interface utilisant les méthodes HTTP (GET, POST, PUT, DELETE) avec des contraintes architecturales :

  • Stateless : Chaque requête contient toutes les informations nécessaires (pas de session côté serveur).
  • Interface uniforme : Les URLs représentent des ressources (/api/agents/12345), les méthodes HTTP représentent les actions (GET=lire, POST=créer, PUT=remplacer, DELETE=supprimer).
  • Représentation : Les données sont structurées en JSON (principalement), XML ou YAML.

Pipelining et Connexions Persistantes

En HTTP/1.0, chaque requête nécessitait l'ouverture d'une nouvelle connexion TCP (3-way handshake + TLS handshake pour HTTPS). HTTP/1.1 a introduit :

  • Keep-Alive : La connexion TCP reste ouverte pour plusieurs requêtes/réponses successives.
  • Pipelining : Le client envoie plusieurs requêtes sans attendre les réponses (technique vue dans l'exercice DGFiP Wireshark — le navigateur réutilise le même port source pour plusieurs requêtes).

QUIC (Quick UDP Internet Connections)

Protocole initialement développé par Google en 2013, repris par l'IETF et normalisé en juin 2021 (RFC 8999 à 9002). Version 2 en mai 2023 (RFC 9369). Destiné à devenir le transport de référence pour HTTP/3.

  • Fonctionne sur UDP (rapidité, traverse les middleboxes) mais implémente un mode connecté et fiable (la fiabilité est gérée par QUIC lui-même, pas par UDP).
  • Fusionne transport et chiffrement : TLS 1.3 est intégré directement dans la poignée de main QUIC. Résultat : une connexion initiale ne nécessite qu'un seul aller-retour (1-RTT) au lieu de trois en TCP+TLS. Pour une reprise de connexion, c'est 0-RTT — les données sont envoyées dès le premier paquet !
  • Protocole géré par l'application (navigateur web, pas le noyau OS) — permet des mises à jour rapides sans attendre les patches OS.
  • Multiplexing sans Head-of-Line Blocking : En TCP, si un paquet d'une image est perdu, toute la page web se fige en attendant la retransmission (car TCP est un flux ordonné unique). Avec QUIC, chaque flux (stream) est indépendant — seule l'image concernée est ralentie, le texte continue de s'afficher normalement.
  • Connection Migration : Si vous passez du Wi-Fi à la 4G, l'adresse IP change, mais QUIC garde la connexion active grâce à un Connection ID unique. En TCP, la connexion serait perdue car elle est identifiée par le quadruplé (IP src, port src, IP dst, port dst).
  • Deux types d'en-tête : Long Header (établissement de connexion, contient le Connection ID complet) et Short Header (échange de données, optimisé en taille).
  • Services compatibles QUIC : HTTP/3, SMB over QUIC (Windows 11), SSH, DNS over QUIC (DoQ), tous les services Google.

Messagerie (SMTP, POP3, IMAP)

Architecture globale

La messagerie utilise plusieurs protocoles complémentaires :

  • SMTP : Pour l'envoi et le relais des messages (client → serveur, et serveur → serveur).
  • POP3 ou IMAP : Pour la récupération des messages par le client dans sa boîte aux lettres.

SMTP (Simple Mail Transfer Protocol)

  • Ports TCP : 25 (relais entre serveurs, en clair), 587 (soumission client avec STARTTLS, recommandé), 465 (SSL/TLS direct, ancien mais de retour)
  • Protocole d'envoi de messages entre serveurs, mode connecté TCP
  • Ne garantit ni la provenance ni la réception (sauf SMTP authentifié). C'est comme la poste : vous pouvez écrire n'importe quel expéditeur sur l'enveloppe.
  • Messages transférés en clair sur le réseau — encodage 7 bits (les accents nécessitent un encodage base64 ou quoted-printable)
  • Un email = une enveloppe (en-têtes : From, To, Subject, Date...) + une ligne vide + un contenu (même principe que HTTP)

Sécurité Anti-Spam moderne : SMTP étant vulnérable à l'usurpation d'identité, 3 standards basés sur les enregistrements DNS TXT sont devenus quasi-obligatoires :
① SPF (Sender Policy Framework) : Liste les IP/serveurs autorisés à envoyer des mails pour le domaine. Ex: v=spf1 ip4:145.242.11.0/24 -all
② DKIM (DomainKeys Identified Mail) : Le serveur signe cryptographiquement chaque mail. La clé publique est publiée en DNS TXT. Le serveur récepteur vérifie la signature.
③ DMARC (Domain-based Message Authentication) : Politique indiquant quoi faire si SPF ou DKIM échouent (rejeter, quarantaine, rien) + adresse de rapport.

POP3 (Post Office Protocol v3)

  • Port TCP 110 (en clair), 995 (POP3S — chiffré TLS)
  • Protocole de réception : télécharge les messages puis les supprime du serveur (comportement par défaut historique, modifiable). Les messages ne sont plus accessibles que sur le client qui les a téléchargés.
  • Protocole simple — pas de gestion de dossiers côté serveur.
  • Commandes : USER, PASS (en clair !), LIST, RETR (récupérer), DELE (supprimer), QUIT
  • Attention : certains anciens serveurs acceptent USER/PASS en clair sans chiffrement → toujours utiliser POP3S (port 995).

IMAP (Internet Message Access Protocol)

  • Port TCP 143 (en clair), 993 (IMAPS — chiffré TLS)
  • Le message reste sur le serveur → consultable depuis plusieurs clients (Smartphone, PC, Webmail). Aujourd'hui, IMAP a totalement remplacé POP3 dans les usages professionnels.
  • Gère des dossiers (Boîte de réception, Envoyés, Corbeille, Spam, dossiers personnalisés).
  • Commandes numérotées (chaque commande est préfixée d'un numéro de séquence — une erreur de séquence provoque une erreur de communication).
  • Mots de passe en base64 (non sécurisé, facilement décodable) → toujours préférer IMAPS (port 993).
  • Supporte la recherche côté serveur, les drapeaux (lu, important, supprimé), et les quotas de boîte aux lettres.

LDAP (Lightweight Directory Access Protocol)

Protocole léger d'accès aux annuaires. Il a été créé pour remplacer le protocole DAP des annuaires X.500 (trop lourd et complexe car basé sur la pile OSI complète). LDAP fonctionne directement sur TCP/IP, le rendant beaucoup plus léger et pratique.

De l'ancienne norme X.500, seule la norme X.509 (format de certificats numériques, utilisé par TLS/HTTPS) est encore largement utilisée aujourd'hui.

Note d'architecture : Microsoft Active Directory (AD), utilisé dans 95% des entreprises pour gérer les sessions Windows des employés, est une implémentation propriétaire qui repose sur LDAP pour l'annuaire (stockage des utilisateurs, groupes, politiques) et Kerberos pour l'authentification (vérification des mots de passe, tickets de session).

Concepts fondamentaux

  • Arborescence hiérarchique (DIT — Directory Information Tree) : Les données sont organisées comme un arbre inversé, de la racine (dc=dgfip,dc=fr) vers les feuilles (les utilisateurs).
  • Entrée (Entry) : Chaque nœud de l'arbre est une entrée identifiée de façon unique par son DN (Distinguished Name).
  • Attributs : Chaque entrée possède des attributs (nom, type, valeur(s)). Un attribut peut avoir plusieurs valeurs (ex: plusieurs numéros de téléphone). Si un attribut n'a pas de valeur, il est simplement absent (contrairement aux SGBDR où il serait NULL).
  • Schéma : Définit les types d'attributs autorisés et les classes d'objets (ex: une personne doit avoir un cn et un sn, et peut avoir un telephoneNumber).

Sécurité réseau

Proxy (serveur mandataire)

Un serveur proxy est un intermédiaire qui réalise une connexion indirecte entre deux machines. Le client ne se connecte jamais directement au serveur distant — il parle au proxy, qui parle au serveur pour lui.

Utilités

  • Accélération de la navigation grâce à l'utilisation de caches (pages web fréquemment demandées stockées localement) et de compression (gzip, brotli)
  • Filtrage de contenu : Sites malveillants bloqués (malware, phishing), filtrage par catégorie (réseaux sociaux, jeux, streaming...), listes noires/blanches
  • Masquage de l'identité : Le poste de travail n'est pas directement accessible depuis le serveur distant — seule l'IP du proxy est visible. Protège les IP internes.
  • Journal d'audit (Logging) : Stockage de toutes les requêtes (URL, date, heure, utilisateur, volume de données). Permet la traçabilité légale des connexions des employés (obligation légale en France).
  • Contournement de restrictions géographiques : En passant par un proxy dans un autre pays (usage hors contexte DGFiP).
  • Antivirus/Anti-malware réseau : Le proxy peut scanner les fichiers téléchargés avant de les transmettre au client.
🏛️

À la DGFiP : le réseau n'est pas connecté directement à Internet. L'accès Internet pour les postes agents se fait uniquement à travers des proxys nationaux. Sans configuration proxy, aucun accès Internet n'est possible depuis un poste DGFiP.

Inspection SSL (MITM légitime)

Aujourd'hui, 95% du web est en HTTPS (chiffré). Un proxy classique ne peut pas lire le contenu chiffré pour filtrer les virus ou les sites malveillants. Pour contourner ce problème, les entreprises déploient l'inspection SSL :

  1. Le client se connecte au proxy en pensant se connecter à google.com.
  2. Le proxy intercepte la connexion et se connecte lui-même à google.com (avec le vrai certificat de Google).
  3. Le proxy déchiffre la page, l'analyse (antivirus, filtrage).
  4. Le proxy rechiffre la page avec son propre certificat d'entreprise (signé par la CA interne, installée dans le magasin de confiance de tous les postes) et l'envoie au client.

Le client voit un cadenas vert car le certificat du proxy est signé par une CA de confiance (celle de l'entreprise). Mais techniquement, c'est un Man-in-the-Middle légitime.

Pare-feu (Firewall)

Système qui filtre les connexions entre les réseaux. Il protège un ordinateur ou un réseau d'ordinateurs des intrusions provenant d'un réseau tiers (notamment Internet) en filtrant les paquets de données échangés selon un ensemble de règles.

La Règle d'Or : Un pare-feu d'entreprise fonctionne toujours en "Default Deny" (Interdiction implicite). La toute dernière règle en bas de la liste est toujours "Tout bloquer". Si un paquet ne correspond à aucune règle d'autorisation au-dessus, il est détruit silencieusement. Les règles sont évaluées de haut en bas — la première qui correspond est appliquée, les suivantes sont ignorées.

Niveaux de filtrage

NiveauCouche OSIFiltrage sur…Exemples de règles
2LiaisonAdresses MACBloquer toute MAC non enregistrée dans la liste blanche
3RéseauAdresses IP, protocolesAutoriser le réseau 10.31.76.0/22 vers 10.154.96.38 en ICMP
4TransportPorts TCP/UDPAutoriser TCP dst:443 (HTTPS), bloquer TCP dst:23 (Telnet)
7ApplicationComportement, contenuBloquer les injections SQL dans les requêtes HTTP, détecter les patterns de scanning de ports. C'est le rôle des NGFW (Next Gen Firewalls) et des WAF (Web Application Firewalls).

Types de pare-feu

Sans état (Stateless) : Décision basée uniquement sur le paquet courant. Les paquets précédents ne sont pas pris en compte. Exemple : les ACL (Access Control Lists) sur les routeurs Cisco. Très rapide mais peu sécurisé : il faut créer des règles explicites dans les deux sens (aller ET retour), ce qui est complexe et source d'erreurs.

Avec état (Stateful) : Décision basée sur le paquet courant + l'historique des paquets précédents (état de la connexion). Le pare-feu garde en RAM une table des sessions actives (connection tracking). Si un PC interne ouvre une connexion web (SYN sortant), le pare-feu laisse automatiquement passer les réponses du serveur web (SYN+ACK, données entrantes) sans avoir besoin d'une règle explicite de retour. C'est le standard minimum en entreprise.

Zone Démilitarisée (DMZ)

Un pare-feu offre la possibilité de créer différentes zones de sécurité avec des règles d'accès distinctes. La DMZ (Zone Démilitarisée) est une zone tampon entre le réseau interne et Internet.

Principe : La DMZ sert à héberger les serveurs qui doivent être accessibles aussi bien de l'intérieur que de l'extérieur (serveur web public, serveur de mail, reverse proxy), sans autoriser l'accès direct aux postes de travail internes.

Concept de sécurité : Si un hacker pirate le serveur Web exposé dans la DMZ, il se retrouve coincé dans cette zone. Le pare-feu lui bloquera l'accès vers le Réseau Interne (où se trouvent les bases de données critiques, les contrôleurs Active Directory et les PC des employés). La compromission est contenue.

Architecture DMZ classique : ┌─────────────────────┐ │ INTERNET │ └──────────┬──────────┘ │ ┌───────┴───────┐ Règles du pare-feu : │ PARE-FEU │ ✅ Internet → DMZ : ports 80, 443 │ (Stateful) │ ✅ Interne → DMZ : tous └───┬───────┬───┘ ✅ Interne → Internet : via proxy │ │ ❌ DMZ → Interne : BLOQUÉ ┌────┴───┐ ┌─┴──────────┐ ❌ Internet → Interne : BLOQUÉ │ DMZ │ │ RÉSEAU │ │ │ │ INTERNE │ │ Web │ │ │ │ Mail │ │ PC agents │ │ Proxy │ │ Serveurs │ │ reverse│ │ BDD │ └────────┘ └────────────┘

Variante "double pare-feu" : Pour encore plus de sécurité, certaines architectures placent deux pare-feux de marques différentes : un entre Internet et la DMZ, un autre entre la DMZ et le réseau interne. Si une faille est découverte dans l'un des pare-feux, l'autre constitue une deuxième ligne de défense.

Passerelle d'Accès Sécurisée (PAS) — DGFiP

Le principe de DMZ a été étendu et généralisé à la DGFiP pour créer de multiples zones de sécurité isolées. La PAS est une plateforme qui permet l'isolation du réseau en plusieurs zones avec des règles de transmission de données (flux) strictement définies entre elles. C'est le principe de la Micro-segmentation.

Version allégée

ZoneDescriptionConnexions autorisées
Zone 1Internet (extérieur)❌ Aucune connexion directe vers les autres zones (passe par le proxy)
Zone 2Serveurs applicatifsAccessible depuis la zone 3. Héberge les applications métier (Ulysse, Odissée...)
Zone 3Postes agents (principale)→ Zone 2 uniquement. C'est la zone où se trouvent les PC des agents.
Zone 4Administration✅ Accès à toutes les zones, aucune zone ne peut y accéder. C'est le réseau de management ultra-restreint (administrateurs système uniquement).
Zone 5Prestataires externesAccès limité et contrôlé aux seuls serveurs nécessaires à leur mission.

Version détaillée

Le détail montre des subdivisions supplémentaires pour une granularité encore plus fine :

  • Deux zones 2 (Privée et Publique) : Certains serveurs applicatifs sont accessibles de l'extérieur (zone 2 Publique = DMZ), mais pas tous (zone 2 Privée = serveurs internes uniquement).
  • Deux zones 3 (3 et 3R) : La zone 3R ("Renforcée") offre un niveau de protection supplémentaire pour certains postes sensibles (ex: postes manipulant des données fiscales confidentielles).
  • Deux zones 4 (4 et 4P) : La zone 4P est accessible en "Push" et sert pour les remontées d'information automatiques (ex: supervision Synaps) sans nécessiter de polling (interrogation régulière depuis la zone 4).
🔒

En fonction de son habilitation et de son profil métier, un utilisateur peut se trouver dans une zone ou une autre, lui conférant plus ou moins de droits d'accès. Les demandes d'ouverture de flux entre zones font l'objet de procédures de validation strictes et documentées — chaque flux est justifié par un besoin métier, approuvé par le RSSI, et tracé.

WireShark — Principes

WireShark est le logiciel de référence pour la capture et l'analyse des paquets passant à portée des interfaces réseau. C'est un outil indispensable pour le diagnostic réseau, la cybersécurité et la compréhension des protocoles. L'analyse est souvent faite à postériori en ouvrant des fichiers de capture (format .pcap ou .pcapng).

Le Mode Promiscuité (Promiscuous Mode)

Par défaut, une carte réseau ignore les trames qui ne lui sont pas destinées (elle ne traite que les trames unicast avec sa MAC, les broadcasts et les multicasts auxquels elle est abonnée). Pour que Wireshark puisse "écouter" tout le trafic qui passe sur le câble ou sur le segment, il force la carte réseau en mode promiscuité, l'obligeant à lire et capturer 100% des trames.

Limitation importante : Sur un réseau switché, le mode promiscuité ne capture que le trafic de votre propre port (unicast vers/depuis votre machine) + le broadcast + le multicast. Pour capturer le trafic d'autres machines, il faut configurer un port miroir (SPAN port) sur le switch, qui copie le trafic d'un port vers votre port de capture.

  • Par valeur hexadécimale (pour chercher un pattern spécifique dans les données brutes)

Checksum Offloading (Le piège classique)

Les interfaces modernes délèguent le calcul du checksum (FCS Ethernet, checksum IP, checksum TCP) à la carte réseau (NIC) matérielle pour soulager le processeur. WireShark capture le paquet au niveau logiciel avant ce calcul matériel :

  • Pour les paquets sortants : le FCS peut apparaître à 0x00000000 et le checksum IP à 0x0000 — ils seront remplis par la NIC juste avant l'envoi sur le câble.
  • Pour les paquets entrants : les checksums sont corrects car ils ont été calculés par la carte réseau distante.

Wireshark affiche ces paquets sortants avec des erreurs en rouge ("Bad checksum", "Frame check sequence: incorrect"). Ce n'est pas une erreur réseau, c'est du Checksum Offloading — un faux positif.

💡

Solution : Dans Éditer → Préférences → Protocols → Ethernet : décocher "Validate the Ethernet checksum if possible". Idem dans Protocols → IPv4 pour "Validate the IPv4 checksum if possible". Cela supprime les fausses alertes visuelles sans affecter l'analyse réelle.

⚠️

Ne pas confondre :
- Filtres d'affichage (langage WireShark) : Appliqués après la capture. Masquent visuellement certains paquets mais ne les suppriment pas — ils restent dans la capture. Syntaxe riche et puissante.
- Filtres de capture (langage BPF — Berkeley Packet Filter) : Appliqués avant l'enregistrement. Seuls les paquets correspondants sont capturés — les autres sont perdus définitivement. Récapitulatif général

🔌 Couche 1 — Physique

  • 3 supports : Cuivre (RJ45), Fibre optique, WiFi (radio)
  • Cuivre : Cat 5e (1G), Cat 6 (1G), Cat 6a (10G), Cat 7 (toléré si RJ45)
  • Blindage : U/F/S — nomenclature ISO 11801 (Global/Paire)
  • PoE : 802.3af (15W), 802.3at (30W), 802.3bt (60/90W)
  • Fibre : Monomode (jaune, longue distance, laser) vs Multimode (orange/turquoise, courte distance, LED/VCSEL)
  • Transceivers SFP/SFP+ : modules enfichables adaptables
  • Fibre obligatoire si >90m ou inter-bâtiments (isolation galvanique)
  • VDI, LTI/LTE, armoires et bandeaux de brassage, cordons
  • Recette câblage : FLUKE 1800 (atténuation, diaphonie, longueur, wire map)
  • WiFi DGFiP : 802.1X / EAP-TLS (certificats), RADIUS

🔗 Couche 2 — Liaison

  • Adresses MAC : 6 octets (OUI 3 oct. + NIC 3 oct.)
  • Sous-couches : LLC (interface couche 3) + MAC (accès au médium)
  • Trame Ethernet II : Préambule, SFD, MAC dst/src, EtherType, Données (46-1500), FCS (CRC-32)
  • Switch : table MAC/CAM, Learning/Forwarding/Flooding/Filtering
  • Modes : Store-and-Forward, Cut-Through, Fragment-Free
  • VLAN : segmentation broadcast, sécurité, QoS
  • Trunk 802.1Q : Tag 4 octets (TPID + PCP + DEI + VID 12 bits)
  • VLAN Natif : non tagué sur le trunk
  • STP 802.1D : Root Bridge, Root Port, Designated Port, Blocking
  • RSTP, PVST+, MSTP — PortFast, BPDU Guard, Root Guard
  • Attaques : MAC Flooding → Port Security, 802.1X

🌐 Couche 3 — Réseau

  • IPv4 : 32 bits, masque/CIDR, ET logique, réseau/broadcast
  • Classes historiques A/B/C/D/E (abandonné → CIDR)
  • Adresses : réservées (127, 169.254, 0.0.0.0), privées RFC 1918 (10/172.16/192.168), publiques
  • VLSM, Subnetting (diviser par 2), Supernetting (agréger)
  • En-tête IPv4 : 20 oct. min (Version, IHL, TOS/DSCP, TTL, Protocol, Checksum, IP src/dst)
  • TTL : décrémenté à chaque routeur, protège des boucles
  • ICMP : ping (Echo Req/Reply), traceroute (Time Exceeded), Destination Unreachable
  • MTU (1500 Ethernet) / MSS (MTU-40) / PMTU Black Hole
  • ARP : IP→MAC, cache (2-3 min), broadcast, GARP, DAI contre ARP Spoofing
  • NAT : SNAT/PAT (sortie, masquerade), DNAT (entrée, port forwarding)
  • Routage : hop-by-hop, Longest Prefix Match, statique/dynamique (OSPF, BGP)
  • MAC change à chaque saut, IP reste identique (sauf NAT)
  • RIE : 10.0.0.0/8, plages /24 et /22, DHCP National

🚚 Couche 4 — Transport

  • TCP : connecté, fiable, 3-way handshake (SYN/SYN+ACK/ACK), SEQ/ACK
  • Fermeture : FIN/ACK/FIN/ACK (4-way), RST = coupure brutale
  • Fenêtre glissante (contrôle de flux), Window Scaling
  • Congestion : Slow Start, Congestion Avoidance, Fast Retransmit/Recovery
  • Attaque SYN Flood → SYN Cookies, pare-feu stateful
  • UDP : non connecté, rapide, 8 octets d'en-tête, best effort
  • Ports : 0-1023 (well-known), 1024-49151 (registered), 49152-65535 (ephemeral)
  • Socket = IP + Port. Quadruplé identifie une connexion.
  • QUIC : UDP connecté + TLS 1.3 intégré, multiplexage, connection migration, 0-RTT

📡 Couches hautes

  • DHCP : DORA (Discover/Offer/Request/Ack), bail, relay DGFiP (ip helper-address), DHCP Snooping
  • DNS : hiérarchie (racine → TLD → domaine), 13 groupes racine, TTL cache
  • DNS : A/AAAA/CNAME/MX/NS/PTR/SOA/SRV/TXT, dig/nslookup/host
  • DNS DGFiP : ns0/ns1.dgfip, ne résout pas Internet, TLD internes (.dgfip, .intranet.dgfip)
  • HTTP : stateless, GET/POST/PUT/DELETE, codes 2xx/3xx/4xx/5xx
  • HTTPS : TLS, certificats X.509, clé de session symétrique
  • HTTP/1.1 → HTTP/2 (multiplexage) → HTTP/3 (QUIC)
  • API REST : méthodes HTTP + JSON, stateless, interface uniforme
  • Messagerie : SMTP (25/587/465), POP3 (110/995), IMAP (143/993)
  • Anti-spam : SPF + DKIM + DMARC (DNS TXT)
  • LDAP (389/636) : annuaire arborescent, DIT, dn/cn/ou/dc, ldapsearch, filtres
  • Active Directory = LDAP + Kerberos

🔒 Sécurité

  • Proxy : intermédiaire, cache, filtrage, audit, proxy.pac (JavaScript)
  • Inspection SSL : MITM légitime pour analyser le HTTPS
  • DGFiP : proxy national obligatoire pour Internet
  • Pare-feu : Default Deny, règles de haut en bas
  • Stateless (ACL) vs Stateful (table de sessions) vs NGFW (couche 7)
  • NetFilter (iptables/nftables), FortiGate, Check Point, Palo Alto
  • DMZ : zone tampon, serveurs exposés, isolation
  • PAS DGFiP : 6+ zones (Internet, Serveurs, Agents, Admin, Prestataires, VPN)
  • Micro-segmentation, ouvertures de flux validées par RSSI
  • Attaques : MAC Flooding, ARP Spoofing, SYN Flood, DHCP Starvation/Rogue
  • Parades : Port Security, DAI, DHCP Snooping, 802.1X, BPDU Guard

🔍 WireShark

  • Capture et analyse de paquets (.pcap, .pcapng)
  • Mode promiscuité — limité par le switch (SPAN port nécessaire)
  • 7 zones : menu, toolbar, filtre, liste, détail, hex, status
  • Filtres d'affichage ≠ filtres de capture (BPF)
  • Filtrage : protocole, champ==valeur, slice [0:3], in{}, opérateurs &&/||/!
  • Recherche Ctrl+F : filtre, string, hex
  • Checksum Offloading : faux positifs FCS/IP/TCP (désactiver validation)
  • Suivre un flux : clic droit → Follow → TCP Stream
  • Filtres utiles : tcp.analysis.retransmission, dns.time, !arp

🛠️ Commandes essentielles

  • ip a / ip l / ip r / ip n — interfaces, liens, routes, ARP
  • ping / tracepath / tracert — connectivité et routage
  • dig / nslookup / host — résolution DNS
  • ss -tulnp / netstat -ano — sockets et connexions
  • curl / wget — requêtes HTTP
  • dhclient / dhclient -r — bail DHCP
  • ldapsearch — interrogation LDAP
  • hostnamectl / nmtui / nmcli — configuration permanente
  • /etc/hosts — résolution locale de noms
  • /etc/resolv.conf — serveurs DNS
  • arp -a (Win) / ip n (Linux) — cache ARP
  • Variables proxy : http_proxy, https_proxy, no_proxy
